### R4. `crates/yarp_core/src/paths.rs:247-249` Windows config-dir layout
gamma flagged in Step 3 review as "verify whether they're upstream-coupled
before changing":
```
"Warp" => "Warp-Terminal".to_owned(),
"WarpOss" => "Warp-Oss".to_owned(),
other if other.starts_with("Warp") => other.replace("Warp", "Warp-Terminal-"),
```
This is a dirs lookup — what app data folder name to use. Renaming is
**RENAME** in principle (we want `yarp` going forward), but it's a
**migration**: existing user data is in `Warp-Terminal-*` directories. If we
flip to `Yarp-Terminal-*` users lose their state on upgrade. So either:
- (a) Keep `Warp-Terminal-*` for backward compat (config is one-way; renaming
  drops user data) — accept the legacy name in the data dir.
- (b) Add migration: read from old path, copy to new, delete old.
**UNDECIDED — needs product call.** Pre-existing OSS users likely don't
have data here yet (`WarpOss` channel data dir), so a clean rename may be
acceptable for OSS-only fork.
- `crates/yarp_core/src/paths_tests.rs:101,118,135` — test fixtures use
  `AppId::new("dev","warp","Warp"/"WarpDev"/"WarpOss")` — these match the
  paths.rs lookup. Update with paths.rs.
